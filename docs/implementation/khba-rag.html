1 · What KHBA is

KHBA is a retrieval-augmented chat assistant for Korean legal and administrative documents (laws, ordinances, administrative rules, interpretations, association guides, member cases). A user asks in natural language; the assistant searches an indexed corpus, grounds its answer in the retrieved passages, and cites every claim back to the exact source document, which the user can open in a side panel.

3 · Data model

The corpus follows the WS-1267 document model: a four-level hierarchy from the logical document down to the smallest citable unit of evidence, which carries the embedding vector.

└── document_versioneffective version at a point in time
└── content_nodearticle / clause / table hierarchy
└── source_evidencesmallest citable unit — holds the embedding

04
Offline · Admin
Ingestion pipeline
manifest → OCR → chunk → embed → upsert

Ingestion turns a source PDF into embedded, searchable source_evidence rows. The document list lives in data/ingest/manifest.json — each entry names a file plus its metadata (code, title, authority type, jurisdiction, security class, version).

Stage 1 — Agentic OCR (lib/ingest/parse.ts)

LlamaCloud's agentic tier parses the whole document in a single OCR + vision + reasoning pass, keeping tables and cross-page layout coherent. Two options matter for RAG quality:

output_options: {
  markdown: {
    tables: {
      output_tables_as_markdown: true,  // pipe tables, not HTML <table>
      merge_continued_tables: true,     // stitch tables spanning pages
    },
  },
}
Stage 4 — Idempotent upsert (lib/ingest/upsert.ts)
  • Deletes existing rows for the same document_code first (cascades), then re-inserts — re-ingesting is always safe.
  • Per chunk: a content_node (path CODE#n) + a source_evidence row.
  • evidence_grade from authority type (LAW→A, ORDINANCE→B, ADMIN_RULE→C, INTERPRETATION→D, ASSOCIATION_GUIDE→E, MEMBER_CASE→F).
  • Embedding cast to halfvec(1536); index_status = INDEXED so it's immediately searchable.

Running it

scripts/ingest.ts (pnpm ingest) drives the whole pipeline. It loads .env, then connects to Supabase's transaction pooler with the settings the pooler requires:

postgres(process.env.DATABASE_URL, {
  ssl: "require",   // pooler rejects plaintext
  prepare: false,   // no prepared statements over the pooler
  max: 1,
})
The pooler gotcha Without ssl: 'require', the connection hangs silently. This was the single biggest blocker during bring-up. The current manifest holds 11 documents — 5 generated Korean samples + 6 Seoul Metropolitan Government ordinances.

5 · Semantic chunking

Fixed-size chunking cuts across sentences and articles; KHBA chunks semantically so each chunk is a topically-coherent unit. lib/ai/chunking.ts does this in three steps:

1 · Paragraphsblank-line split; long ones sub-split
→
2 · Embedevery base unit
→
3 · Mergedistance < 0.12 → merge; else new chunk
Why paragraph-first
  • Paragraphs are the natural unit for legal text. Long paragraphs are sub-split by langchain's RecursiveCharacterTextSplitter with a separator list tuned for Korean & English.
  • Merge pass: each unit is embedded, then adjacent units merge while cosine distance < 0.12 AND combined length < 1200 chars. A topic shift starts a new chunk.
Bug fixed along the way An earlier version collapsed each document to a single chunk (the minimum-size threshold was too high). The paragraph-first design fixed that.

6 · Embeddings

lib/ai/embeddings.ts wraps the Vercel AI SDK's embed / embedMany over OpenAI text-embedding-3-small.

ItemValue
EMBEDDING_MODEL_IDtext-embedding-3-small
EMBEDDING_DIMENSIONS1536
embedText(value)single vector — used for the query at retrieval time
embedTexts(values)batch via embedMany — used during chunking & ingestion
Dimension is load-bearing 1536 is fixed to match the halfvec(1536) column. Change the model and you must change the column dimension and re-embed the whole corpus.

7 · Semantic retrieval

semanticSearchKhba(query, limit) in lib/ai/retrieval.ts is the read path. It embeds the query, then runs a cosine-distance search over source_evidence.

Query→ 1536-d vector
→
Cosine searchsim = 1 − distance
→
Over-fetch ×4dedupe by document_code
→
Top resultsbest passage / document
Hard filters (unauthenticated endpoint)
  • security_class = 'PUBLIC'
  • deleted_at IS NULL
  • index_status = 'INDEXED'
  • evidence_embedding IS NOT NULL

One result per document: over-fetch limit × 4 rows and dedupe by document_code, keeping each document's best-matching passage.

Full-document view getDocumentByCode(code) returns the entire latest version of a PUBLIC document — all passages ordered by their stored chunkIndex — so the user reads the whole thing, not just the cited snippet.

8 · Chat agent

lib/ai/khba-agent.ts defines a single ToolLoopAgent (Vercel AI SDK v7) used by the /api/chat route handler.

UserPOST messages → /api/chat
└── AgentprepareStep compacts prior-turn snippets
└── searchKhbasemanticSearchKhba → pgvector → { query, count, results }
└── Answerstreamed text with [n](cite:n) citations
Configuration
  • Model: openai('gpt-4o-mini').
  • Instructions: call searchKhba first, ground the answer, cite inline as [n](cite:n). Never invent a citation.
  • Step budget: stopWhen: stepCountIs(5).
  • prepareStep compacts historical search results (see §9).
No fabrication The searchKhba tool returns no results on failure rather than inventing sources — the assistant then honestly says nothing relevant was found.

9 · Context compaction

A multi-turn conversation re-sends prior tool results on every step. Each searchKhba result carries full passage snippets, so a long chat balloons the model's context. lib/ai/compact-history.ts fixes this via prepareStep.

Prior turn — full (before)

query + 5 results, each with full snippet text — hundreds of tokens, re-sent every step.

Compacted for the model (after)

query + citation map: n → documentCode, authorityType, securityClass. No snippets.

How it stays grounded
  • Historical searchKhba calls are identified by their toolCallId in initialMessages.
  • Those results' output.value is replaced with the compact citation map.
  • The current turn's result is left fully intact.
  • Only what the model sees is rewritten — the UI stream is untouched.

10 · Frontend chat experience

The chat UI (components/chat/*) is built on the Vercel AI SDK React hooks. ChatPane orchestrates the whole surface.

Streaming & citations
  • useChat drives messages; sendMessage({ text }) posts to /api/chat. A fresh /chat mints a UUID, stashes the first message, routes to /chat/[id].
  • Answers contain [n](cite:n) links. Markdown preserves the cite: scheme and renders each as a CitationChip. Clicking opens the source panel.
  • Source cards: pulled from the tool part (state output-available).
Panel, suggestions, polish
  • Search skeleton shows while the tool part is in an input state.
  • ArtifactPanel lazy-loads the full document via React Query, highlights the cited passage, falls back to the snippet.
  • useObject streams up to 4 suggestions; useCompletion streams the title.
  • Scroll auto-follows only when at the bottom (useLayoutEffect, no flicker).
11
Prototype · POC
Durable ingestion — Vercel Workflow
Build-verified; not the default path

The CLI script is fine locally, but agentic OCR is slow and occasionally flaky, and a serverless function would time out. workflows/ingest.ts prototypes a durable version with the Vercel Workflow SDK.

ocrStep'use step' — expensive OCR, isolated so a later failure never re-runs OCR
└── indexStep'use step' — chunk + embed + upsert; embeddings stay inside the step
└── workflowingestDocumentWorkflow — deterministic orchestrator; all I/O in steps
Trigger & wiring
  • app/api/ingest/route.ts is a requireAuth-gated POST that fans out one run per document, returning run IDs immediately.
  • next.config.ts wraps the config with withWorkflow, generating the /.well-known/workflow/v1/* routes.
Scope of the POC The durable path runs only via the Next app (the withWorkflow runtime), not via tsx. pnpm ingest remains the CLI path; the workflow is the production-shaped alternative.
